# Phase 1.3 hand-off — re-point open-brain at the shared observability stack

**Status:** PREPARED 2026-07-01, NOT applied. This is a **cross-repo** change to `github.com/davistroy/open-brain` (`docker-compose.yml`). It must go through the open-brain repo → CI → redeploy — not a hand-edit of the appdata clone. Author: observability migration orchestrator (homeserver repo).

## Goal
The GPL stack (Grafana/Prometheus/Loki/Pushgateway) is now the standalone `observability` compose project on the homeserver (Phase 1.1–1.4, live). open-brain must stop *owning* those services and instead **join the `observability` network as a client** so the shared Prometheus can scrape `core-api:3000/metrics` and the workers can push to `pushgateway:9091`. This also resolves the current transient alerts (`WorkersMetricsAbsent`, core-api target down).

## The change (3 edits to open-brain `docker-compose.yml`)

### Edit 1 — declare the external `observability` network
```diff
 networks:
   open-brain:
     driver: bridge
+  observability:
+    external: true          # shared fleet stack (homeserver/observability): provides prometheus + pushgateway DNS
```

### Edit 2 — attach the two app services that need cross-stack DNS
`core-api` (must be scrapable by the shared Prometheus) and `workers` (must push to the shared Pushgateway):
```diff
   core-api:
     ...
     networks:
       - open-brain
+      - observability        # shared Prometheus scrapes core-api:3000/metrics
```
```diff
   workers:
     ...
     networks:
       - open-brain
+      - observability        # workers push to the shared pushgateway:9091
```
(No other app service exposes a scraped `/metrics` — the shared `prometheus.yml` only scrapes `core-api:3000` + `pushgateway:9091` among open-brain targets — so only these two need the second network.)

### Edit 3 — delete the 4 GPL service definitions + their now-unused named volumes
Remove the entire `loki:`, `pushgateway:`, `prometheus:`, `grafana:` service blocks (the `# ── Observability stack ──` section, all `profiles: [observability]`-gated). Then remove the three now-orphaned named volumes from the top-level `volumes:` block:
```diff
 volumes:
   postgres_data:
   redis_data:
   whisper_model_cache:
   financial_ingest_data:
   utility_ingest_data:
   admin_prewipe_backup:
-  prometheus_data:
-  grafana_data:
-  loki_data:
   voice_spool_data:
```

## Non-changes (leave as-is) — verify, don't edit
- **`x-logging` anchor stays** `loki-url: ${LOKI_URL:-http://localhost:3100/loki/api/v1/push}`. The Docker Loki log **driver** runs in the daemon and ships to the host's `127.0.0.1:3100`, which `observability-loki` now serves. `LOKI_URL` in `.env.secrets` must remain `localhost` (NOT a container DNS name). No change.
- **`PUSHGATEWAY_URL`** (consumed by `packages/workers/src/lib/push-metrics.ts`, set in `.env.secrets`) should be **`http://pushgateway:9091`** — unchanged; it now resolves to `observability-pushgateway` via the `observability` network once `workers` joins it. **Verify the current value**; if it names a specific container (e.g. `open-brain-pushgateway`), change it to `pushgateway:9091`.
- The `config/{loki,prometheus,grafana}/` files in the open-brain repo become **unused** (the observability stack carries its own verbatim copies). Leave them or delete in a later cleanup — not required for this change.

## 🛑 CRITICAL — pre-existing volume-drift landmine (fix BEFORE any redeploy)
Verified live 2026-07-01 (`docker inspect` on the running containers + both compose files):
- The deployed `docker-compose.yml` **and** GitHub `main` both declare `postgres_data`, `redis_data`, `prometheus_data`, `grafana_data`, `loki_data` as **plain named volumes** (no `driver_opts`).
- `docker-compose.override.yml` (appdata-only, **not in git** — 404) only remaps **ports** (core-api `3002:3000`, redis `6380:6379`). It does **not** define bind mounts.
- But the **running** containers use **bind mounts**: `open-brain-postgres` → `/mnt/user/appdata/open-brain/pgdata`, `open-brain-redis` → `/mnt/user/appdata/open-brain/redis-data` (GPL data dirs likewise). They were created from an **older** compose that has since been overwritten with named-volume definitions **without redeploying**.

**Consequence:** the compose files no longer match the running containers. A full `docker compose up -d` (no service args) — or a CI redeploy from `main` — would see Postgres/Redis "config changed" (bind → named), **recreate them onto empty named volumes, and detach them from their real data.** (Data isn't destroyed — it stays at the bind paths — but Postgres/Redis would come up empty until the compose is fixed.) This landmine exists **today, independent of observability**; the 1.3 change just must not trip it.

**Reconcile FIRST** — restore explicit bind-device volume defs so the compose matches the running mounts, e.g.:
```yaml
volumes:
  postgres_data:
    driver: local
    driver_opts: { type: none, o: bind, device: /mnt/user/appdata/open-brain/pgdata }
  redis_data:
    driver: local
    driver_opts: { type: none, o: bind, device: /mnt/user/appdata/open-brain/redis-data }
  # …audit EVERY data volume against `docker inspect` before any `up -d`
```
Also: the real deploy is a **manual `docker compose up -d` from the appdata dir** (auto-merges the port override) — **not** a CI-from-`main` redeploy (which would also lose the port override). Confirm the actual deploy mechanism; "route through CI" may not match reality.

### Fastest SAFE way to get 1.3's effect (given the landmine)
Because any container **recreate** risks the landmine, the safe fast path to 1.3's *functional* goal (core-api scraped + workers pushing → transient alerts clear) is the **runtime network bridge**, which recreates nothing:
```
docker network connect observability open-brain-core-api
docker network connect observability open-brain-workers
```
Reversible (`docker network disconnect`), ~15 min to clear alerts, and superseded cleanly whenever the durable compose change is applied. The durable repo change (volume reconciliation + the 3 topology edits + a careful redeploy) can then follow without time pressure.

## Collision note (until this ships)
The 4 GPL services are `profiles: [observability]`-gated, so a plain `docker compose up -d` on open-brain will **not** restart them. Only an explicit `docker compose --profile observability up -d` would — and that would collide with the live shared stack on ports 3050/9090/3100/9091. Don't run open-brain with `--profile observability` until this change removes those services.
